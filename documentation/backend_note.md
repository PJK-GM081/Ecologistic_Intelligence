# Backend Developer Guide

This guide explains what the ML layer provides, how to run it from a clean device, and what the backend should expose.

## What ML Provides

Artifacts generated by the ML workflow:

- `models/random_forest_model.pkl` - trained Random Forest classifier.
- `artifacts/encoders/preprocessor.pkl` - fitted preprocessing transformer.
- `artifacts/metadata/preprocessing_metadata.pkl` - feature names and global aggregation means.
- `data/processed/*.csv` - train/test features and labels generated from raw data.

Runtime services:

- `PredictionService` - loads model/preprocessor and predicts shipment delay risk.
- `AnalyticsService` - reads raw operational data and returns dashboard aggregations.
- `InterpretationService` - explains one shipment using local SHAP when available, with safe fallbacks.

## Fresh Device Workflow

These generated folders are ignored by Git and may not exist on a new device:

- `data/processed/`
- `models/`
- `artifacts/`
- `logs/`

That is expected. Rebuild them with:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env

python main.py --mode preprocess
python main.py --mode train
python run_api.py
```

Equivalent full pipeline:

```bash
python main.py --mode full
python run_api.py
```

API docs:

```text
http://127.0.0.1:8000/docs
http://127.0.0.1:8000/redoc
```

## Environment

`.env` is local and ignored by Git. Use `.env.example` as the tracked template.

Important variables:

```env
API_HOST=127.0.0.1
API_PORT=8000
API_WORKERS=4
LOG_LEVEL=INFO
RAW_DATA_PATH=data/raw/DataCoSupplyChainDataset.csv
MODEL_PATH=models/random_forest_model.pkl
PREPROCESSOR_PATH=artifacts/encoders/preprocessor.pkl
METADATA_PATH=artifacts/metadata/preprocessing_metadata.pkl
```

## API Convention

Use one route convention only: `/api/*`.

Current routes:

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Health check |
| POST | `/api/predict` | Predict shipment delay risk |
| GET | `/api/analytics/home` | Dashboard summary |
| GET | `/api/analytics/region` | Region list or region detail via `?region=` |
| GET | `/api/analytics/distribution` | Chart-ready distribution data |
| POST | `/api/explain/shipment` | Single-shipment explanation |
| GET | `/api/features/importance` | Sampled/global feature importance |

No non-API aliases such as `/predict` or `/analytics/home` should be exposed.

## Prediction Request

```bash
curl -X POST http://127.0.0.1:8000/api/predict ^
  -H "Content-Type: application/json" ^
  -d "{\"region\":\"Western Europe\",\"shipping_mode\":\"Standard Class\",\"category\":\"Fishing\",\"quantity\":3,\"days_for_shipment\":4,\"sales\":250.0}"
```

Request schema:

```json
{
  "region": "Western Europe",
  "shipping_mode": "Standard Class",
  "category": "Fishing",
  "quantity": 3,
  "days_for_shipment": 4,
  "sales": 250.0,
  "benefit_per_order": 0.0,
  "customer_segment": "Consumer",
  "market": "Europe",
  "order_month": 5,
  "order_dayofweek": 1,
  "is_weekend": 0
}
```

Only `region`, `shipping_mode`, `category`, and `quantity` are required.

Response shape:

```json
{
  "status": "success",
  "data": {
    "risk_probability": 0.3564,
    "risk_level": "LOW",
    "risk_score": 36,
    "predicted_class": 0,
    "explanation": "Low risk of shipment delay (35.6%). Shipment appears on track.",
    "input_features": {}
  },
  "metadata": {
    "timestamp": "...",
    "latency_ms": 12.3,
    "model_loaded": true
  }
}
```

## Analytics Endpoints

Home dashboard:

```bash
curl http://127.0.0.1:8000/api/analytics/home
```

Returns:

- `dashboard_summary`
- `regional_risk`
- `shipping_mode_risk`
- `category_risk`

Region:

```bash
curl "http://127.0.0.1:8000/api/analytics/region?region=Western Europe"
```

Distribution:

```bash
curl "http://127.0.0.1:8000/api/analytics/distribution?dimension=risk"
```

Supported dimensions:

- `risk`
- `region`
- `shipping_mode`
- `mode`
- `category`
- `market`
- `customer_segment`

## Explanation Endpoint

```bash
curl -X POST http://127.0.0.1:8000/api/explain/shipment ^
  -H "Content-Type: application/json" ^
  -d "{\"region\":\"Western Europe\",\"shipping_mode\":\"Standard Class\",\"category\":\"Fishing\",\"quantity\":3,\"risk_probability\":0.65}"
```

Response includes:

- `top_factors`
- `dominant_driver`
- `explanation`
- `method` (`local_shap`, `model_importance`, or `heuristic`)

Backend should rate-limit or cache this route in production because SHAP can be slower than analytics/prediction.

## Backend Responsibilities

Backend should:

- Expose the `/api/*` endpoints.
- Keep artifact paths configurable.
- Standardize HTTP error responses.
- Add production auth, CORS policy, monitoring, and rate limits.
- Add cache TTL policy for analytics and feature importance if needed.

Backend should not:

- Reimplement feature engineering.
- Recompute SHAP for the full dashboard.
- Train models inside normal API request flow.
